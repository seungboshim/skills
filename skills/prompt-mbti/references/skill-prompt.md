# 스킬 생성 프롬프트 만들기

반복이 확인되면 "스킬로 만들어보세요"에서 끝내지 않는다.
**그 사람의 패턴으로 채운 프롬프트를 통째로 만들어 준다.** 복사해서 에이전트에 붙이면
스킬이 나오게.

## 언제 내나

지표에서 아래 중 하나라도 걸리면 낸다.

- `## 자동화 후보` 에 같은 명령이 **20회 이상** 반복됐다
- `## 작업 방식` 의 스킬 호출이 **지시 100건당 5회 미만**이다
- 말버릇 상위에 같은 요청 유형이 반복해서 보인다

셋 다 아니면 내지 않는다. 반복이 없는데 스킬을 만들라고 하면 헛일을 시키는 것이다.

## 무엇을 재료로 쓰나

지표에 있는 숫자만 쓴다. 없는 사실을 지어내지 않는다.

| 재료 | 어디서 | 프롬프트의 어디에 |
| --- | --- | --- |
| 반복 명령과 횟수 | `## 자동화 후보` | 무엇을 자동화할지 |
| 도구 분포 | `## 작업 방식` | 어떤 도구를 쓰는 스킬인지 |
| 스킬·서브에이전트 호출 수 | `## 작업 방식` | 왜 지금 필요한지 |
| 저장소 목록 | `## 활동 범위` | 어디서 쓸 스킬인지 |
| 말버릇 상위 | `## 말버릇` | 어떤 요청이 잦은지 |

## 먼저 이렇게 말을 건다

숫자를 앞에 놓고 제안한다. 근거 없이 권하면 잔소리로 읽힌다.

> 도구를 43,573번 부르는 동안 스킬은 199번 불렀습니다. 지시 100건당 7회입니다.
> 그중 `npx tsc` 를 481번, `npm test` 를 189번 직접 쳤습니다.
> 같은 순서를 반복하고 있다면 그건 스킬의 자리입니다.
>
> 아래를 에이전트에 그대로 붙여넣으면 스킬 초안이 나옵니다.

## 프롬프트 형식

아래 골격에 그 사람의 숫자를 채운다. 대괄호는 전부 실제 값으로 바꾼다.

````markdown
스킬을 하나 만들려고 해. 내 실제 작업 기록에서 뽑은 패턴이야.

## 내가 반복하는 것

[반복 명령 상위 3개를 횟수와 함께. 예: `npx tsc` 481회, `npm test` 189회]

## 내 작업 방식

- 주로 쓰는 도구: [상위 3개와 비중]
- 서브에이전트 호출: [횟수] (지시 100건당 [N]회)
- 스킬 호출: [횟수] (지시 100건당 [N]회)
- 주로 일하는 곳: [저장소 상위 2~3개]

## 만들고 싶은 것

위 반복을 대신하는 스킬. 이름은 [제안 이름]으로 생각 중이야.

이 스킬이 할 일:
1. [반복 명령에서 유추한 첫 단계]
2. [두 번째 단계]
3. [결과를 어떻게 보여줄지]

## 지켜줬으면 하는 것

- 판단이 필요 없는 부분은 스크립트로 두고, 스크립트가 낸 값을 모델이 다시 계산하지 않게 해줘
- 실패하거나 판단하기 어려운 상황에서 무엇을 하는지 문서에 적어줘
- 자기 점검을 붙여줘. 값을 아는 입력을 넣고 결과를 대조하는 방식으로

SKILL.md 와 필요한 스크립트를 만들어줘.
````

## 이름을 제안하는 방법

반복 명령의 목적어를 쓴다. 동사 + 대상 두 단어면 충분하다.

- `npx tsc` 와 `npm test` 가 반복 → `pre-commit-check`
- `git log` 와 `git diff` 가 반복 → `change-digest`
- 같은 저장소에서 `grep` 이 반복 → 검색 대상을 이름으로

정할 수 없으면 이름 자리를 비우고 "이름은 네가 정해줘"로 둔다.

## 하지 말 것

- **특정 스킬 이름을 권하지 않는다.** 남이 만든 스킬을 설치하라고 하지 말고,
  그 사람의 패턴으로 새로 만들게 한다
- 반복 횟수가 적은데 억지로 프롬프트를 만들지 않는다
- 프롬프트 안의 숫자를 어림하지 않는다. 지표에 있는 값을 그대로 옮긴다
- 한 번에 스킬 후보를 여러 개 주지 않는다. **가장 많이 반복된 것 하나**만
