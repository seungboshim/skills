# prompt-mbti — 진단으로 끝나지 않습니다

Claude Code, Codex, Hermes 에 그동안 타이핑한 지시를 세어 프롬프트 습관을 진단하고,
가장 치우친 축 두 개에 대해 **다음에 복사해 쓸 문장**을 주는 스킬입니다.

## 결과는 유형이 아니라 다음에 쓸 문장입니다.

성격 검사는 보통 유형을 알려주고 끝납니다. 그래서 다음 날 아무것도 안 바뀝니다.

prompt-mbti 는 마지막에 붙여 쓸 문장을 통째로 줍니다.
조언이 아니라 복사해서 그대로 지시창에 넣을 문장입니다.

> **W 산개형**: 저장소를 옮기면 첫 지시에 붙입니다.
> `여기는 (프로젝트 이름). 규칙 하나: (그 프로젝트만의 규칙)`
>
> before: `아까처럼 해줘`
> after: `여기는 kbo-card-gacha. 규칙 하나: 여기선 tailwind 안 쓰고 CSS 모듈이야`

## 코칭은 16유형이 아니라 축 여덟 개로 씁니다.

유형마다 코칭을 따로 쓰면 문서가 열여섯 장이 되고, 축을 하나 추가하는 순간 서른두 장이
됩니다. 그래서 **축 여덟 개(네 축 × 양극단)만 쓰고 유형 코드에서 꺼내 조합합니다.**

축을 하나 더해도 코칭 문서는 두 줄만 늘어납니다. 유형은 서른둘이 되고요.

| 축 | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| 말수 | S 단문형 | L 장문형 |
| 시간 | D 주행성 | N 야행성 |
| 태도 | T 위임형 | V 검증형 |
| 범위 | W 산개형 | F 집중형 |

## 넷 중 둘만 줍니다.

네 축을 다 지적하면 아무것도 안 고칩니다. 가장 치우친 축 두 개만 고릅니다.

치우침은 눈금 한가운데가 아니라 **축 임계값에서 얼마나 떨어졌는지**로 잽니다.
축마다 단위가 달라서 임계값으로 나눠 비율로 맞춥니다. 새벽 3% 는 임계값 15% 에서
0.80 만큼, 확인 요청 18% 는 임계값 25% 에서 0.28 만큼 떨어져 있습니다.

## 코칭 문서를 갈아 끼우면 팀 규칙이 됩니다.

`references/coaching.md` 한 장이 전부입니다. 축 여덟 개에 각각 문장 한 쌍씩 들어 있습니다.
팀에서 쓰는 표현이 따로 있으면 그 파일만 바꿔 쓰면 됩니다. 스크립트는 손대지 않습니다.

임계값도 마찬가지입니다. `references/types.md` 와 스크립트 두 곳의 숫자만 맞추면
"우리 팀은 확인 요청 40% 부터 검증형"으로 바꿀 수 있습니다.

## 다음 달에 다시 재면 처방이 먹혔는지 숫자로 나옵니다.

결과지를 날짜별로 저장합니다. 다시 돌리면 **축이 바뀐 것만** 짚어 한 줄 덧붙입니다.

> 두 달 전에는 검증형이었습니다.

코칭에서 실행으로, 실행에서 재측정으로 닫힙니다. 한 번 보고 마는 검사가 아닙니다.

## 유형은 어디서 나오나.

문항에 답하지 않습니다. 도구들이 이미 쌓아둔 세션 기록을 셉니다.

`/prompt-mbti` 를 치면 구간을 묻고, Claude Code·Codex·Hermes 에서 사람이 직접 타이핑한
지시만 골라내 네 축을 잽니다. 에이전트 답변, 도구 결과, 스킬이 끼워 넣은 문장은 뺍니다.

| 구간 | 결과지 |
| --- | --- |
| 오늘 | 오늘 한 장면. 표본이 작아 유형은 내지 않습니다 |
| 일주일 | 추세. 지난 결과지와 무엇이 달라졌나 |
| 한 달 | 유형 카드. 요즘의 나 |
| 전체 | 유형 카드. 성격 검사 |

| 축 | 지표 | 기준 |
| --- | --- | --- |
| 말수 | 지시 길이 중앙값 | 60자 |
| 시간 | 새벽 0~5시 비중 | 15% |
| 태도 | 확인·검증 요청 비중 | 25% |
| 범위 | 최다 저장소 편중도 | 50% |

```bash
bash scripts/analyze.sh --days 30 --out /tmp/m.md   # 숫자를 확정한다
bash scripts/render.sh /tmp/m.md --png              # 카드로 만든다
```

숫자는 `analyze.sh` 가 확정하고 모델은 해석만 합니다. 같은 데이터에 같은 코드가 나오게
계산을 스크립트에 묶었습니다. `render.sh` 는 그 숫자를 옮기기만 하고 새로 계산하지 않습니다.

## 길이는 평균이 아니라 중앙값으로 잽니다.

에러 로그를 한 번 붙여넣으면 평균이 수천 자로 튀어서 말버릇을 못 보여줍니다.
2000자를 넘는 지시는 붙여넣기로 보고 길이 계산에서 뺍니다.

기본 상한은 최근 3000건입니다. 기록이 그보다 많으면 오래된 것부터 빼고 몇 건을 뺐는지
적습니다. 지금 습관이 궁금한 것이지 두 해 전 습관이 궁금한 게 아니기 때문입니다.

## 같은 사람이 도구마다 다르게 말합니다.

```
Claude Code : 지시 1791건 · 중앙값 75자 · 물음표 59% · 확인 요청 15% · 새벽 1%
Codex       : 지시 1208건 · 중앙값 69자 · 물음표 42% · 확인 요청 22% · 새벽 7%
```

실제 측정값입니다. 클로드에는 묻고 코덱스에는 시킵니다.
물음표가 17포인트 벌어집니다. 한 도구만 봐서는 나오지 않는 결과입니다.

## 원문 지시를 출력하지 않습니다.

읽는 파일에는 그동안 타이핑한 지시가 전부 들어 있습니다. 그래서 경계를 이렇게 잡았습니다.

- 스크립트는 수치와 낱말 빈도만 냅니다. 자기 점검 항목으로 고정했습니다
- 네트워크를 쓰지 않습니다. 전부 로컬 파일을 읽고 로컬에 저장합니다
- Hermes 의 SQLite 는 읽기 전용으로 엽니다. 실행 중인 Hermes 를 막지 않습니다
- 낱말 빈도에 사내 용어가 올라올 수 있어, 내보내기 전에 순위를 다시 읽고 걸러냅니다
- 저장소 이름이 목록에 그대로 나옵니다. 발행할 때 가릴지 물어봅니다

## 못 하는 것을 먼저 밝힙니다.

- 지시가 100건 미만이면 "표본 주의"를 붙입니다. 작은 표본의 유형을 성향처럼 설명하지 않습니다
- 임계값에서 3포인트 안쪽이면 "경계형"이라고 적습니다. 한쪽으로 밀지 않습니다
- 기록 형식이 옛 버전이면 완화된 기준으로 골라내고, 그 사실을 결과 첫머리에 적습니다
- Hermes 는 작업 경로를 저장하지 않아, 편중도 축은 경로를 아는 지시만으로 계산하고 뺀
  건수를 밝힙니다. 경로 없는 도구가 축을 왜곡하면 안 되기 때문입니다
- `jq` 가 없으면 멈춥니다. 반쯤 센 숫자를 내지 않습니다
- 지표에 없는 추론을 하지 않습니다. 인격도 평가하지 않습니다.
  "성급한 사람이다"가 아니라 "확인 요청이 18%다"로 씁니다

## 단정 30개로 매번 확인합니다.

`bash scripts/test-analyze.sh` 를 돌리면 값을 아는 가짜 기록을 세 도구 모양으로 심고
결과를 대조합니다. 원문이 새지 않는지, 에이전트 답변과 스킬 주입이 집계에서 빠지는지,
상한이 걸렸을 때 몇 건을 뺐는지 밝히는지, 카드에 코칭이 정확히 두 개만 붙는지가
단정에 들어 있습니다.

Claude Code 세션 1146개(931MB)와 Codex 세션 226개를 훑어 직접 타이핑한 지시
3539건을 골라내는 데 약 7초 걸립니다. 두 번 돌려 같은 결과가 나오고, 구간을 좁혀도
같은 유형 코드가 나옵니다.

낱말 집계는 `jq` 의 `scan` 으로 합니다. BSD `grep` 은 자모 범위를 콜레이션 순서로 읽어
오류로 끝나고, `-o` 로 한 줄에 여러 번 나온 것을 다 세지 못하기 때문입니다.
macOS 에서 실제로 겪고 바꿨습니다.

## 옵션

```bash
--today          # 오늘만. 새벽 5시에 하루를 끊는다
--days 7         # 최근 7일
--max 10000      # 분석 상한 (기본 3000, 최근 것부터)
--source claude  # 한 도구만 (all | claude | codex | hermes)
--png            # render.sh 에서 PNG 까지 만든다
```

## 설치

```bash
/plugin marketplace add seungboshim/skills
/plugin install prompt-mbti@seungboshim-skills
```

`jq` 가 필요합니다. macOS 는 `brew install jq`.
Hermes 기록을 읽으려면 `sqlite3`, PNG 카드를 만들려면 헤드리스 크롬이 있어야 합니다.
둘 다 없어도 나머지는 동작합니다.
