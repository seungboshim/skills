# prompt-mbti

**문항이 없는 성격 검사. 이미 내가 한 말을 셉니다.**

Claude Code, Codex, Hermes 에 그동안 타이핑한 지시를 전부 세어 프롬프트 습관을 진단하는
스킬입니다. 네 축으로 16유형 중 하나를 내고, 근거가 된 숫자를 전부 같이 보여줍니다.

## 흔한 방식과 무엇이 다른가

성격 검사의 흔한 방식은 문항입니다. "나는 계획적인 편이다"에 사람이 답합니다.
그 답은 자기 인식이지 행동이 아닙니다. 프롬프트를 잘 쓰라는 조언도 마찬가지입니다.
"더 구체적으로 지시하세요"는 맞는 말이지만, 내가 지금 얼마나 구체적인지를 알려주지 않습니다.

prompt-mbti 는 묻지 않습니다. **도구들이 이미 쌓아둔 세션 기록을 셉니다.**

여기가 접근이 갈리는 지점입니다. 에이전트를 쓴 기록은 원래 "무엇을 만들었나"의 재료로만
쓰입니다. 이 스킬은 같은 기록을 뒤집어 **"어떻게 시켰나"의 재료로** 씁니다.
대화 기록이 산출물이 아니라 행동 로그가 됩니다.

그래서 나오는 숫자가 자기 인식과 다릅니다. 중앙값 72자로 길게 쓰는 사람이 승인은
`ㄱㄱ` 두 글자로 한다는 사실은 물어봐서는 절대 안 나옵니다.

### 도구를 여러 개 쓰면 더 갈립니다

한 도구만 보면 "나는 이렇게 지시한다" 한 줄로 끝납니다.
**여러 도구를 같이 재면 같은 사람이 도구마다 다르게 말한다는 게 드러납니다.**

```
Claude Code : 지시 1791건 · 중앙값 75자 · 물음표 59% · 확인 요청 15% · 새벽 1%
Codex       : 지시 1208건 · 중앙값 69자 · 물음표 42% · 확인 요청 22% · 새벽 7%
```

실제 측정값입니다. 같은 사람인데 클로드에는 묻고 코덱스에는 시킵니다.
물음표가 17포인트 차이납니다. 한 도구만 봐서는 나올 수 없는 결과입니다.

## 어떻게 쓰나

### 입력

없습니다. `/prompt-mbti` 라고 치거나 "내 프롬프트 습관 분석해줘"라고 말하면 됩니다.
스킬이 먼저 구간을 묻고, 고르면 나머지는 알아서 진행합니다.

| 구간 | 결과지 |
| --- | --- |
| 오늘 | 오늘 한 장면. 표본이 작아 유형은 내지 않습니다 |
| 일주일 | 추세. 지난 결과지와 무엇이 달라졌나 |
| 한 달 | 유형 카드. 요즘의 나 |
| 전체 | 유형 카드. 성격 검사 |

"오늘"은 새벽 5시에 하루를 끊습니다. 새벽 3시 작업은 어제 것으로 셉니다.

### 처리

1. `scripts/analyze.sh` 가 `~/.claude/projects`(Claude Code), `~/.codex/sessions`(Codex CLI),
   `~/.hermes/state.db`(Hermes CLI)에서 **사람이 직접 타이핑한 지시만** 골라냅니다.
   에이전트 답변, 도구 결과, 스킬이 끼워 넣은 문장은 뺍니다. 있는 도구만 읽고 나머지는
   0건으로 결과 첫머리에 적습니다
2. 지시 길이, 시간대, 확인 습관, 저장소 편중도, 말버릇 빈도를 셉니다
3. 스크립트가 임계값을 적용해 **유형 코드를 확정합니다.** 모델은 판정을 다시 하지 않고
   해석만 합니다. 같은 데이터에 같은 코드가 나오게 하려고 계산을 스크립트에 묶었습니다
4. `scripts/render.sh` 가 그 숫자로 결과지 카드(HTML·PNG)를 만듭니다.
   숫자를 새로 계산하지 않고 옮기기만 합니다

```bash
bash scripts/analyze.sh --days 30 --out /tmp/m.md   # 숫자를 확정한다
bash scripts/render.sh /tmp/m.md --png              # 카드로 만든다
```

기본 상한은 **최근 3000건**입니다. 기록이 그보다 많으면 오래된 것부터 빼고 몇 건을
뺐는지 적습니다. 지금 습관이 궁금한 것이지 두 해 전 습관이 궁금한 게 아니기 때문입니다.

### 네 축

| 축 | 지표 | 기준 | 코드 |
| --- | --- | --- | --- |
| 말수 | 지시 길이 중앙값 | 60자 미만 / 이상 | S 단문형 / L 장문형 |
| 시간 | 새벽 0~5시 지시 비중 | 15% 미만 / 이상 | D 주행성 / N 야행성 |
| 태도 | 확인·검증을 요청한 지시 비중 | 25% 미만 / 이상 | T 위임형 / V 검증형 |
| 범위 | 최다 저장소 편중도 | 50% 미만 / 이상 | W 산개형 / F 집중형 |

길이는 평균이 아니라 **중앙값**으로 잽니다. 에러 로그를 한 번 붙여넣으면 평균이 수천 자로
튀어서 사람의 말버릇을 못 보여줍니다. 2000자를 넘는 지시는 붙여넣기로 보고 길이 계산에서
뺍니다.

### 결과

실제 실행 결과입니다. 저장소 이름만 가렸습니다.

```

말수  S 단문형 ————●———— L 장문형    중앙값 72자
시간  D 주행성 ●———————— N 야행성    새벽 3%
태도  T 위임형 ——●—————— V 검증형    확인 요청 18%
범위  W 산개형 ———●————— F 집중형    최다 저장소 41%
```

**임계값에서 3포인트 안쪽이면 경계형이라고 적습니다.** 검사지가 아니라 지표이므로
억지로 한쪽으로 밀지 않습니다.

## 그래서 뭘 바꾸나

카드 아래에 **가장 치우친 축 두 개**의 코칭이 붙습니다. 지시하지 않고 붙여 쓸 문장을
통째로 줍니다.

> **W 산개형**
> 저장소를 옮기면 첫 지시에 붙입니다.
> `여기는 (프로젝트 이름). 규칙 하나: (그 프로젝트만의 규칙)`
>
> before: `아까처럼 해줘`
> after: `여기는 kbo-card-gacha. 규칙 하나: 여기선 tailwind 안 쓰고 CSS 모듈이야`

치우침은 눈금 한가운데가 아니라 **축 임계값에서 얼마나 떨어졌는지**로 잽니다.
축마다 단위가 달라서 임계값으로 나눠 비율로 맞춥니다. 넷을 다 주면 아무것도 안 고치므로
두 개만 줍니다.

## 언제 반복해서 쓰나

한 달에 한 번 정도가 맞습니다. 습관은 하루 만에 안 바뀝니다.

반복해서 쓸 때 값이 생기는 지점은 **비교**입니다. 결과지를 날짜별로 저장하므로, 다음에
돌리면 축이 바뀐 것만 짚어 한 줄 덧붙입니다. "두 달 전에는 검증형이었다" 같은 문장이
나옵니다. 처방을 실행했는지가 다음 측정에서 숫자로 드러납니다.

## 다른 상황에도 쓸 수 있나

- 구간을 바꿉니다. `--today`, `--days 7`, `--days 30`, 전체
- 한 도구만 봅니다. `--source claude|codex|hermes`
- 상한을 조절합니다. `--max 10000`
- 팀에서 각자 돌려 비교할 수 있습니다. 유형 코드가 같은 규칙으로 나오기 때문입니다
- 임계값을 바꾸려면 `references/types.md` 와 스크립트 두 곳을 함께 고칩니다
- 16유형 설명과 축별 코칭은 각각 문서 한 장이라 팀 문화에 맞게 갈아 끼울 수 있습니다

세 도구 중 하나라도 쓴 기록이 있으면 설정 없이 돌아갑니다. 프로젝트 구조를 전제하지 않습니다.

## 실패할 때와 안 하는 것

- `jq` 가 없으면 **멈추고** 설치 방법을 알려줍니다. 반쯤 센 숫자를 내지 않습니다
- 지시가 0건이면 결과지를 쓰지 않습니다. 세 도구 어느 쪽에도 기록이 없다는 뜻입니다
- 지시가 100건 미만이면 유형은 내되 **표본 주의**를 붙입니다. 작은 표본의 유형을 고정된
  성향처럼 설명하지 않습니다
- `--days` 나 `--max` 에 0이나 문자가 들어오면 조용히 잘못된 구간을 계산하지 않고 멈춥니다
- 기록에 `typed` 표시가 없는 옛 버전이면 완화된 기준으로 골라내고, **그 사실을 결과
  첫머리에 적습니다.** "도구 출력이 섞일 수 있다"까지 같이 씁니다
- Hermes 는 작업 경로를 저장하지 않습니다. 그래서 편중도 축은 **경로를 아는 지시만으로**
  계산하고 뺀 건수를 밝힙니다. 경로 없는 도구가 축을 왜곡하면 안 되기 때문입니다
- 지표에 없는 추론을 하지 않습니다. 저장소 이름으로 무슨 일을 하는지 짐작하지 않습니다
- 인격을 평가하지 않습니다. "성급한 사람이다"가 아니라 "확인 요청이 18%다"로 씁니다

## 개인정보와 외부 행동

이 스킬이 읽는 파일에는 그동안 타이핑한 지시가 전부 들어 있습니다. 그래서 경계를 이렇게
잡았습니다.

- 스크립트는 **원문 지시를 출력하지 않습니다.** 수치와 낱말 빈도만 냅니다.
  자기 점검 항목으로 고정해 두었습니다
- 네트워크를 쓰지 않습니다. 전부 로컬 파일을 읽고 로컬에 저장합니다
- Hermes 의 SQLite 는 **읽기 전용으로 엽니다.** 실행 중인 Hermes 를 막지 않습니다
- 낱말 빈도에는 사내 용어가 올라올 수 있습니다. 결과지를 밖으로 내보내기 전에 말버릇
  순위를 다시 읽고, 나가면 안 되는 낱말이 있으면 **사용자에게 알리고 뺍니다**
- 저장소 이름이 목록에 그대로 나옵니다. 발행할 때 가릴지 물어봅니다

## 작동 근거

- 자기 점검이 붙어 있습니다. `bash scripts/test-analyze.sh` 를 돌리면 값을 아는 가짜 세션
  기록을 세 도구 모양으로 심고 **단정 30개**를 확인합니다. 유형 코드가 예상대로 확정되는지,
  원문 지시가 출력에 새지 않는지, 에이전트 답변과 스킬 주입이 집계에서 빠지는지, 상한이
  걸렸을 때 몇 건을 뺐는지 밝히는지, 카드에 코칭이 두 개만 붙는지가 단정에 들어 있습니다
- 실측 규모입니다. Claude Code 세션 파일 1146개(931MB)와 Codex 세션 226개를 훑어 직접
  타이핑한 지시 3539건을 골라내는 데 약 7초입니다
- 재현성을 확인했습니다. 두 번 돌려 같은 결과가 나오고, 구간을 좁혀도 같은 유형 코드가
  나옵니다
- 낱말 집계는 `jq` 의 `scan` 으로 합니다. BSD `grep` 은 자모 범위를 콜레이션 순서로 읽어
  오류로 끝나고, `-o` 로 한 줄에 여러 번 나온 것을 다 세지 못하기 때문입니다.
  macOS 에서 실제로 겪고 바꿨습니다

## 설치

```bash
/plugin marketplace add seungboshim/skills
/plugin install prompt-mbti@seungboshim-skills
```

`jq` 가 필요합니다. macOS 는 `brew install jq`.
Hermes 기록을 읽으려면 `sqlite3`, PNG 카드를 만들려면 헤드리스 크롬이 있어야 합니다.
둘 다 없어도 나머지는 동작합니다.
