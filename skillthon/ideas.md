# 스킬톤 아이디어 지도

기준은 다섯 가지다. `기상천외함 / 유용함 / 완성도 / 재사용성 / 신뢰성`을 각각 10점으로
보되, 1차 심사가 ZIP을 열지 않는다는 점 때문에 **한 장의 결과 화면으로 가치가 보이는가**를
별도로 강하게 봤다.

## 지금 가장 강한 열 개

| 순위 | 아이디어 | 한 문장 | 강한 이유 | 주의점 |
| --- | --- | --- | --- | --- |
| 1 | diggz-radio | 현재 코드 상태와 원하는 감정 방향을 인디 저점 트랙의 에너지 곡선으로 컴파일한다 | 도메인 특화·실제 재생·강한 결과 화면이 한 번에 보인다 | 자동 디깅은 API 키나 웹 검색이 필요하다 |
| 2 | prompt-mbti | 질문지 없이 에이전트에게 이미 한 말을 세어 프롬프트 습관 16유형을 낸다 | 한 문장에 전환점·실측·결과 화면이 다 있다 | Claude Code 기록이 필요하다 |
| 3 | truman | 커밋·reflog·세션 발언을 하루짜리 관찰예능으로 만들고 미완성을 차회 예고로 남긴다 | 웃기지만 마지막은 실제 회고다 | 인용 공유 전 민감정보 점검 필요 |
| 4 | date-sim | 숨은 니즈가 있는 가상 소개팅을 진행하고 내 발언을 부검한다 | 현장 시연과 반복 훈련이 쉽다 | 판타지 역할극으로 보이지 않게 설명해야 한다 |
| 5 | promise-ledger | 고객 대화에서 우리 쪽이 한 약속만 뽑아 기한·담당·미이행을 추적한다 | Rescoop의 실제 도메인 지식이 드러난다 | 메시지 접근 수단이 필요하다 |
| 6 | betrayal-map | 별점이 아니라 “기대가 깨진 순간”으로 리뷰를 묶는다 | 흔한 감성 분석과 관점이 다르다 | 리뷰 원문이 적으면 과도한 군집화를 멈춰야 한다 |
| 7 | korean-hidden-subject | 한국어 요구사항에서 생략된 주어·책임자·기한을 찾아 질문으로 돌려준다 | 한국어 특화이고 업무 재사용성이 높다 | 교정 스킬과 경계를 분명히 해야 한다 |
| 8 | card-fit-autopsy | 카드 추천 질문지 대신 실제 소비 내역에서 버린 혜택과 놓친 혜택을 부검한다 | 기존 카드 플러그인 경험과 연결된다 | 금융 권유가 아니라 비교 근거 제공으로 한정해야 한다 |
| 9 | agent-trust-thermometer | 세션 기록에서 사용자가 언제 재확인하고 언제 맡기는지 측정해 자율성 설정을 추천한다 | prompt-mbti보다 행동 처방에 집중한다 | 생산성·성격으로 확대 해석하면 안 된다 |
| 10 | letter-archivist | 손편지 사진을 전사하되 애매한 글자는 채우지 않고 기억 단서와 출처를 함께 보존한다 | channy의 도메인과 신뢰 경계가 선명하다 | OCR·이미지 입력이 필요하다 |

## 고객 대화·리뷰 도메인 — Rescoop에서 꺼낼 것

1. **promise-ledger** — 고객에게 “확인해드릴게요”, “금요일까지”라고 한 약속만 원문 근거와 함께 장부로 만든다.
2. **betrayal-map** — 리뷰의 주제가 아니라 사용자의 기대가 깨진 정확한 순간으로 묶는다.
3. **silent-thread** — 답이 끊긴 스레드에서 마지막으로 해소되지 않은 질문과 멈춘 이유 후보만 찾는다.
4. **launch-canary** — 출시 직후 메시지에서 아직 빈도는 낮지만 손실이 큰 약한 신호를 찾는다.
5. **reply-risk-gate** — 환불·법적 위협·개인정보가 섞인 답변은 초안을 쓰기 전에 승인 경로부터 정한다.
6. **creator-collab-triage** — 인플루언서 협업 DM에서 금액보다 먼저 빠진 조건·사용권·일정을 찾는다.
7. **policy-drift** — 실제 상담 답변과 최신 정책 문서가 갈라진 문장만 짚는다.
8. **complaint-to-test** — 반복 불만을 재현 가능한 QA 시나리오로 바꾸되 원문에 없는 단계를 만들지 않는다.

## 관계·기억 도메인 — channy와 편지함에서 꺼낼 것

9. **letter-archivist** — 손글씨를 전사하면서 불확실한 글자를 `[?]`로 남기고 원본 좌표를 붙인다.
10. **memory-index** — 편지·티켓·사진을 날짜, 사람, 장소, 약속으로 인덱싱하고 추정은 별도 표시한다.
11. **reply-angle** — 답장을 대신 써주지 않고 상대가 꺼낸 세 가지 화제와 되물어볼 한 가지를 고른다.
12. **promise-in-letters** — 과거 편지에서 함께 하자고 한 일을 찾아 기념일 전에 다시 꺼낸다.
13. **relationship-weather** — 진단 대신 명시된 감정 표현의 변화만 기간별로 보여준다.
14. **keepsake-caption** — 오래된 물건 사진에 “누가·언제·왜 남겼나”를 질문해 기억 손실을 막는다.

## 대화·사회성 훈련 도메인

15. **date-sim** — 숨은 니즈·지뢰·난이도가 있는 소개팅과 발언 부검.
16. **group-chat-entry** — 이미 친한 사람들 사이에 들어갈 때 화제 끼어들기와 질문 타이밍을 훈련한다.
17. **feedback-rehearsal** — 동료에게 불편한 피드백을 주고 방어적 반응이 왔을 때 다시 말하는 법을 훈련한다.
18. **boundary-gym** — 거절·일정 변경·부탁 거절을 공격적이지 않게 연습하고 과잉 해명을 센다.
19. **complaint-counter** — 고객센터에 사실·요구·양보 가능선을 나눠 말하는 훈련을 한다.
20. **small-talk-ladder** — 단답에서 공통점·경험·감정으로 한 단계씩 넓히는 연습만 반복한다.

## 개발자·에이전트 사용 도메인

21. **prompt-mbti** — 실제 프롬프트 행동 로그 기반 16유형.
22. **truman** — 하루 개발 흔적을 관찰예능으로 편집한 회고.
23. **instruction-debt** — 여러 세션에서 반복한 지시를 찾아 프로젝트 규칙으로 내릴 후보만 만든다.
24. **steering-autopsy** — 실패한 에이전트 세션에서 최초 오해, 늦은 교정, 반복 지시를 시간순으로 부검한다.
25. **commit-lie-detector** — 커밋 메시지가 실제 diff보다 넓거나 좁게 말한 부분을 찾는다.
26. **revert-museum** — reflog에서 사라진 시도를 복원해 왜 버렸는지 묻는 작은 전시를 만든다.
27. **handoff-checksum** — 세션 전후 핸드오프에서 사라진 결정·미확인 가정·다음 행동을 대조한다.
28. **reviewer-diversity** — 같은 diff를 보안·성능·사용자 관점 세 명이 보고 겹치지 않는 위험만 남긴다.
29. **undo-budget** — 실행 계획에서 되돌리기 어려운 행동을 먼저 세고 승인 지점을 배치한다.
30. **context-funeral** — 오래된 문서와 코드가 믿고 있는 전제가 죽었는지 찾아 묘비명 형태로 남긴다.

## 한국어·문체 도메인 — korean-tone에서 꺼낼 것

31. **korean-hidden-subject** — 생략된 주어·책임자·시점 때문에 실행할 수 없는 문장을 질문 목록으로 바꾼다.
32. **apology-architect-ko** — 한국어 사과문을 책임·영향·복구·재발 방지로 나누고 비어 있는 부분만 묻는다.
33. **honorific-router** — 상대와 관계를 먼저 확인하고 호칭·높임·완곡함을 일관되게 맞춘다.
34. **translationese-diff** — 원문 의미와 코드 좌표를 잠근 채 번역투가 걷힌 차이만 보여준다.
35. **multi-agent-editor** — 여러 에이전트가 쓴 문서를 한 사람의 높임과 용어 체계로 합친다.
36. **meeting-ambiguity-ko** — “검토 예정”, “진행 필요” 같은 무주어 명사문을 실제 담당자 질문으로 바꾼다.

## 스포츠·카드·게임 도메인

37. **my-era-roster** — 출생연도가 아니라 팬이 기억하는 경기·선수·유니폼으로 ‘내 시대’ 대표팀을 만든다.
38. **salary-cap-dream-team** — 예산 안에서 라인업을 짜고 무엇을 포기했는지까지 설명한다.
39. **trade-regret** — 당시 규정과 선수 정보만 써서 트레이드의 대체 역사를 두 갈래로 시뮬레이션한다.
40. **gacha-economy-auditor** — 확률·천장·재화 흐름을 시뮬레이션해 운이 아닌 설계의 압력을 찾는다.
41. **boxscore-story** — 박스스코어만으로 승부가 갈린 세 장면을 복원하고 모르는 감정은 만들지 않는다.
42. **scout-vs-stats** — 선수 선택을 스카우트와 세이버 관점이 변론하고 공통 합의와 남은 위험을 낸다.

## 다음에 만들 순서

오늘 출품은 실제 플레이어 화면까지 보이는 `diggz-radio`가 가장 눈에 띈다. API 연결 없이도
로컬 분석이 전부 도는 `prompt-mbti`는 안전한 백업이다. 다음 스프린트는 Rescoop 도메인의
`promise-ledger`가 좋다. 고객 대화에서 이미 반복 사용 장면이 있고, “요약” 대신 “우리의 약속”만
센다는 판단 기울기가 분명하다. 그다음은 `korean-hidden-subject`, `card-fit-autopsy` 순서가 좋다.
