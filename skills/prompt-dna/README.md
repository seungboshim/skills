# prompt-dna

**성격 검사인데 문항이 없다. 이미 내가 한 말을 센다.**

그동안 에이전트에게 타이핑한 지시를 전부 세어 지시 습관을 진단하는 Claude Code 스킬입니다.
Claude Code, Codex, Hermes 기록을 함께 모아 네 축으로 16유형 중 하나를 내고, 근거가 된
숫자를 전부 같이 보여줍니다.

## 흔한 방식과 무엇이 다른가

성격 검사의 흔한 방식은 문항입니다. "나는 계획적인 편이다"에 사람이 답합니다.
그 답은 자기 인식이지 행동이 아닙니다. 프롬프트 습관을 개선하라는 조언도 마찬가지입니다.
"더 구체적으로 지시하세요"는 맞는 말이지만, 내가 지금 얼마나 구체적인지를 알려주지 않습니다.

prompt-dna 는 묻지 않습니다. **에이전트 도구들이 이미 쌓아둔 세션 기록을 셉니다.**

여기가 접근이 갈리는 지점입니다. 에이전트를 쓴 기록은 원래 "무엇을 만들었나"의 재료로만
쓰입니다. 이 스킬은 같은 기록을 뒤집어서 **"어떻게 시켰나"의 재료로** 씁니다.
대화 기록이 산출물이 아니라 행동 로그가 됩니다.

그래서 나오는 숫자가 자기 인식과 다릅니다. 긴 설명을 쓰는 사람이 승인은 `ㄱㄱ` 두 글자로
한다는 사실은 물어봐서는 절대 안 나옵니다.

### 도구를 여러 개 쓰면 더 갈립니다

한 도구만 보면 "나는 이렇게 지시한다" 한 줄로 끝납니다. **두 도구를 같이 재면 같은 사람이
도구마다 다르게 말한다는 게 드러납니다.**

```
Claude Code: 지시 1774건 · 중앙값 75자 · 물음표 59% · 확인 요청 15% · 새벽 1%
Codex:       지시 1746건 · 중앙값 65자 · 물음표 39% · 확인 요청 19% · 새벽 5%
```

실제 측정값입니다. 같은 사람인데 클로드에는 묻고 코덱스에는 시킵니다. 물음표가 20포인트
차이납니다. 이건 한 도구만 봐서는 나올 수 없는 결과입니다.

## 어떻게 쓰나

### 입력

없습니다. `/prompt-dna` 라고 치거나 "내 프롬프트 습관 분석해줘"라고 말하면 됩니다.

### 처리

1. `scripts/analyze.sh` 가 `~/.claude/projects`(Claude Code), `~/.codex/sessions`(Codex CLI),
   `~/.hermes/state.db`(Hermes CLI)에서 **사람이 직접 타이핑한 지시만** 골라냅니다.
   에이전트 답변, 도구 결과, 스킬이 끼워 넣은 문장은 뺍니다. 있는 도구만 읽고 나머지는
   0건으로 결과 첫머리에 적습니다
2. 지시 길이, 시간대, 확인 습관, 저장소 편중도, 말버릇 빈도를 셉니다
3. 스크립트가 임계값을 적용해 **유형 코드를 확정합니다.** 모델은 판정을 다시 하지 않고
   해석만 합니다. 같은 데이터에 같은 코드가 나오게 하려고 계산을 스크립트에 묶었습니다
4. 결과지를 만들어 `~/.claude/prompt-dna/report-YYYY-MM-DD.md` 로 저장합니다

### 네 축

| 축 | 지표 | 기준 | 코드 |
| --- | --- | --- | --- |
| 말수 | 지시 길이 중앙값 | 60자 미만 / 이상 | S 단문형 / L 장문형 |
| 시간 | 새벽 0~5시 지시 비중 | 15% 미만 / 이상 | D 주행성 / N 야행성 |
| 태도 | 확인·검증을 요청한 지시 비중 | 25% 미만 / 이상 | T 위임형 / V 검증형 |
| 범위 | 최다 저장소 편중도 | 50% 미만 / 이상 | W 산개형 / F 집중형 |

길이는 평균이 아니라 **중앙값**으로 잽니다. 에러 로그를 한 번 붙여넣으면 평균이 수천 자로
튀어서 사람의 말버릇을 못 보여줍니다. 2000자를 넘는 지시는 붙여넣기로 보고 길이 계산에서 뺍니다.

### 결과

실제 실행 결과입니다. 저장소 이름만 가렸습니다.

```
LDTW · 총괄 기획자
측정 구간 2026-02-03 ~ 2026-08-15 · 지시 3520건 (Claude Code 1774 · Codex 1746)
세션 245개 · 활동한 날 85일 · 저장소 46개

말수    지시 길이 중앙값 71자        → L 장문형
시간    새벽 3%                      → D 주행성
태도    확인 요청 17%                → T 위임형
범위    최다 저장소 35%              → W 산개형

도구별
- Claude Code: 중앙값 75자 · 물음표 59% · 확인 요청 15% · 새벽 1%
- Codex:       중앙값 65자 · 물음표 39% · 확인 요청 19% · 새벽 5%

눈에 띄는 숫자
- 말버릇 1위가 `다시` 241회. 2위 `그리고`(235회)보다 많다
- 질책·되돌리기 26%, 칭찬·수락 10%. 되돌리는 말이 두 배 반이다
- `ㄱㄱ` 72회, `ㅇㅋ` 43회, `ㄴㄴ` 19회. 긴 설명을 쓰는 사람이 승인은 두 글자로 한다
- 새벽 1%인데 오늘은 03시에 작업 중이다. 이 세션이 통계에서 튀는 쪽이다

처방
반복해서 쓰는 설명을 프로젝트 문서로 내려서 매번 안 쓰게 만든다.
```

**임계값에서 3포인트 안쪽이면 경계형이라고 적습니다.** 위 결과에서 편중도 47%가 그렇습니다.
검사지가 아니라 지표이므로 억지로 한쪽으로 밀지 않습니다.

지시가 100건 미만이면 결과 첫머리에 **표본 주의**가 붙습니다. 유형은 보여주되, 기록이 적을 때
나온 코드를 고정된 성향처럼 설명하지 않습니다.

## 언제 반복해서 쓰나

한 달에 한 번 정도가 맞습니다. 습관은 하루 만에 안 바뀌기 때문입니다.

반복해서 쓸 때 값이 생기는 지점은 **비교**입니다. 결과지를 날짜별로 저장하므로, 다음에 돌리면
축이 바뀐 것만 짚어 한 줄 덧붙입니다. "두 달 전에는 검증형이었다" 같은 문장이 나옵니다.
처방을 실행했는지 아닌지가 다음 측정에서 숫자로 드러납니다.

한 번만 쓰는 용도로도 성립합니다. `--days 30` 으로 최근 한 달만 재면 "요즘의 나"가 나옵니다.

## 다른 상황에도 쓸 수 있나

- 구간을 바꿉니다. 전체 이력이 기본이고 `--days 30` 으로 최근만 잽니다
- 팀에서 각자 돌려 비교할 수 있습니다. 유형 코드가 같은 규칙으로 나오기 때문입니다
- 임계값을 바꾸려면 `references/types.md` 와 스크립트 두 곳을 함께 고칩니다. 문서에 그렇게
  적어뒀습니다
- 16유형 설명은 문서 한 장이라 팀 문화에 맞게 갈아 끼울 수 있습니다

Claude Code, Codex, Hermes 중 하나라도 쓴 기록이 있으면 설정 없이 돌아갑니다.
프로젝트 구조를 전제하지 않습니다.

## 실패할 때와 안 하는 것

- `jq` 가 없으면 **멈추고** 설치 방법을 알려줍니다. 반쯤 센 숫자를 내지 않습니다
- 지시가 0건이면 결과지를 쓰지 않습니다. 세 도구 어느 쪽에도 기록이 없다는 뜻입니다
- 지시가 100건 미만이면 임시 결과라는 경고를 붙입니다
- `--days` 에 0이나 문자가 들어오면 조용히 잘못된 구간을 계산하지 않고 즉시 멈춥니다
- 기록에 `typed` 표시가 없는 옛 버전이면 완화된 기준으로 골라내고, **그 사실을 결과 첫머리에
  적습니다.** "도구 출력이 섞일 수 있다"까지 같이 씁니다. 숫자만 보여주고 출처를 숨기지
  않습니다
- 지표에 없는 추론을 하지 않습니다. 저장소 이름으로 무슨 일을 하는지 짐작하지 않습니다
- 인격을 평가하지 않습니다. "성급한 사람이다"가 아니라 "확인 요청이 15%다"로 씁니다

## 개인정보와 외부 행동

이 스킬이 읽는 파일에는 그동안 타이핑한 지시가 전부 들어 있습니다. 그래서 경계를 이렇게 잡았습니다.

- 스크립트는 **원문 지시를 출력하지 않습니다.** 수치와 낱말 빈도만 냅니다.
  이건 자기 점검 항목으로 고정해 두었습니다
- 네트워크를 쓰지 않습니다. 전부 로컬 파일을 읽고 로컬에 저장합니다
- 낱말 빈도에는 사내 용어가 올라올 수 있습니다. 결과지를 밖으로 발행하기 전에 말버릇 순위를
  다시 읽고, 나가면 안 되는 낱말이 있으면 **사용자에게 알리고 뺍니다**
- 저장소 이름이 목록에 그대로 나옵니다. 발행할 때 가릴지 물어봅니다
- 발행은 사용자가 요청할 때만 합니다

## 작동 근거

- 자기 점검이 붙어 있습니다. `bash scripts/test-analyze.sh` 를 돌리면 값을 아는 가짜 세션
  기록을 세 도구 모양으로 심고 **단정 25개**를 확인합니다. 유형 코드가 `SNTF` 로 확정되는지,
  원문 지시가 출력에 새지 않는지, `typed` 가 아닌 기록과 에이전트 답변이 집계에서 빠지는지,
  두 소스를 합쳤을 때 도구별 건수가 맞는지가 단정에 들어 있습니다
- 실측 규모입니다. Claude Code 세션 파일 1146개(931MB)와 Codex 세션 226개를 훑어 직접
  타이핑한 지시 3520건을 골라냅니다
- 재현성을 확인했습니다. 두 번 돌려 같은 결과가 나오고, `--days 7` 로 구간을 좁혀도 같은 유형
  코드가 나옵니다
- 낱말 집계는 `jq` 의 `scan` 으로 합니다. BSD `grep` 은 자모 범위를 콜레이션 순서로 읽어
  오류로 끝나고, `-o` 로 한 줄에 여러 번 나온 것을 다 세지 못하기 때문입니다. macOS 에서
  실제로 겪고 바꿨습니다

## 설치

```bash
/plugin marketplace add seungboshim/skills
/plugin install prompt-dna@seungboshim-skills
```

`jq` 가 필요합니다. macOS 는 `brew install jq`.
