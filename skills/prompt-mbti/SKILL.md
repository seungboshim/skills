# 프롬프트 MBTI

에이전트에게 한 말은 전부 남아 있다. 이 스킬은 그걸 세어서 내 지시 습관을 보여준다.

성격 검사의 형식을 쓰지만 근거는 전부 실제 숫자다. 문항에 답하는 게 아니라
이미 해온 말을 센다. **없는 사실을 채워 넣으면 이 스킬은 그냥 운세가 된다.**

## 순서

1. 지표를 뽑는다
2. 유형을 읽는다
3. 결과지를 쓴다
4. 저장하고, 원하면 발행한다

## 1. 지표 뽑기

**절대 경로로 부른다.** 이 스킬을 불러올 때 하네스가 알려준 base directory 를 그대로 쓴다.
작업 디렉터리는 사용자의 프로젝트라서 상대 경로로는 못 찾는다.

```bash
bash "<이 스킬의 base directory>/scripts/analyze.sh" --out /tmp/prompt-mbti.md \
  && cat /tmp/prompt-mbti.md
```

base directory 를 모르면 이렇게 찾는다.

```bash
find ~/.claude ~/.config -name analyze.sh -path '*prompt-mbti*' 2>/dev/null | head -1
```

- 기본은 **찾을 수 있는 도구 전부**다. `~/.claude/projects`(Claude Code),
  `~/.codex/sessions`(Codex CLI), `~/.hermes/state.db`(Hermes CLI)를 읽는다.
  있는 것만 읽고 없는 도구는 0건으로 밝힌다
- 한 도구만 보고 싶다고 하면 `--source claude|codex|hermes`
- Hermes 는 `sqlite3` 가 있어야 읽는다. 없으면 그 소스만 건너뛴다
- Hermes 는 작업 경로를 저장하지 않는다. 그래서 **편중도 축은 경로를 아는 지시만으로**
  계산하고, 뺀 건수를 결과에 적는다
- `jq` 가 없으면 멈춘다. 그때는 `brew install jq` 를 안내하고 끝낸다
- 지시가 0건이면 결과지를 쓰지 않는다. 에이전트를 쓴 기록이 없다는 뜻이다
- 지시가 100건 미만이면 유형은 내되 **표본 주의**를 결과 첫머리에 붙인다. 작은 표본의
  유형을 고정된 성향처럼 설명하지 않는다

### 구간을 먼저 물어본다

**스킬을 부르면 제일 먼저 구간을 묻는다.** 지표부터 뽑고 나서 묻지 않는다.
구간에 따라 결과지가 아예 다르기 때문이다.

`AskUserQuestion` 으로 묻는다. header 는 `구간`, 선택지는 아래 넷을 그대로 쓴다.
사용자가 이미 "오늘", "요즘", "최근 일주일" 처럼 말했으면 **묻지 말고 그대로 간다.**

| 고른 것 | 옵션 | 결과지 |
| --- | --- | --- |
| 오늘 | `--today` | 오늘 한 장면. 유형을 내지 않는다 |
| 일주일 | `--days 7` | 추세. 지난 결과지와 무엇이 달라졌나 |
| 한 달 | `--days 30` | 유형 카드. 요즘의 나 |
| 전체 | (없음) | 유형 카드. 성격 검사 |

`--today` 는 새벽 5시에 하루를 끊는다. 새벽 3시 작업은 어제 것으로 센다.
`truman` 스킬의 방송일과 같은 규칙이라 두 스킬의 "오늘"이 어긋나지 않는다.

기본 상한은 **최근 3000건**이다. 기록이 그보다 많으면 오래된 것부터 빼고 결과에 몇 건을
뺐는지 적는다. 사용자가 "전부 다 봐줘" 라고 하면 `--max 99999` 로 올린다. 상한이 있는 건
지금 습관이 궁금한 것이지 두 해 전 습관이 궁금한 게 아니기 때문이다.

스크립트가 마지막에 `## 축 판정` 으로 **유형 코드를 확정해서 준다.** 그 계산을 다시
하지 않는다. 임계값 판정은 스크립트가 하고, 해석은 이 스킬이 한다.

### 그다음 바로 카드를 만든다

지표를 뽑았으면 묻지 말고 결과지 카드까지 만든다. 사람이 보는 건 이 카드다.

```bash
bash "<base directory>/scripts/render.sh" /tmp/prompt-mbti.md --png
```

HTML 과 PNG 경로를 사용자에게 알려준다. 크롬이 없으면 PNG 만 건너뛰고 HTML 은 남는다.

유형 캐릭터 그림이 `assets/characters/<코드>.png` 에 있으면 카드 상단에 들어간다.
`~/.claude/prompt-mbti/characters/` 에 같은 이름을 두면 그쪽이 이긴다. 없으면 그 자리를
비우고 카드는 그대로 나온다. **그림이 없다고 멈추지 않는다.**
카드 레이아웃과 색은 `render.sh` 안에 고정돼 있다. **매번 같은 모양으로 나와야 하므로
디자인을 그때그때 바꾸지 않는다.**

## 2. 유형 읽기

`references/types.md` 에서 확정된 코드의 항목을 읽는다. 축 임계값 표도 그 문서에 있다.

지표가 임계값에서 3포인트 안쪽이면 **경계형**으로 적는다. 예를 들어 새벽 비중이
13% 면 주행성이지만 두 칸만 넘으면 야행성이라고 같이 말한다. 한쪽으로 밀지 않는다.

## 3. 결과지

**구간마다 쓰는 것이 다르다.** 아래 표를 먼저 보고 어느 쪽인지 정한다.

### 오늘 (`--today`)

유형 카드를 내지 않는다. 표본이 열 몇 건인데 성격을 판정하면 그냥 운세다.
대신 **오늘 한 장면**을 쓴다. 다섯 줄 안쪽.

- 오늘 지시 몇 건, 어느 도구로, 어느 저장소에서
- 시간대가 몰린 구간 하나
- 오늘 제일 많이 쓴 낱말 하나
- 어제와 비교할 결과지가 있으면 달라진 것 한 줄

톤은 담담하게 사실만 쓴다. 하루를 이야기로 만들고 싶으면 그건 `truman` 스킬의 일이다.
여기서는 숫자만 짚고 끝낸다.

### 일주일 (`--days 7`)

유형 카드는 내되 **작게** 두고, 지난 결과지와의 차이를 앞에 놓는다.
`~/.claude/prompt-mbti/` 에 이전 결과지가 없으면 차이 블록을 빼고 이번 주 숫자만 쓴다.

### 전체 (기본)

아래 순서로 쓴다. 전체 1000자 안쪽. 결과지는 읽는 데 1분이어야 한다.

| 블록 | 내용 |
| --- | --- |
| 유형 카드 | `LDTW · 총괄 기획자` 와 네 축의 판정값을 한 줄씩 |
| 근거 | 유형을 만든 숫자 네 개. 중앙값, 새벽 비중, 확인 비중, 편중도 |
| 습성 | types.md 의 두 줄을 이 사람의 숫자로 다시 쓴다 |
| 도구별 | 기록이 두 도구 이상이면 넣는다. 아래 규칙을 따른다 |
| 눈에 띄는 숫자 | 지표에서 가장 이상한 것 두세 개. 말버릇·자모 순위도 여기 |
| 처방 | types.md 의 처방 하나. 늘리지 않는다 |

## 코칭이 이 스킬의 목적이다

카드는 재미와 시각화를 맡는다. **사람이 실제로 바꾸는 건 코칭이다.**
그래서 코칭을 낼 때 아래 순서를 지킨다.

### 1. 처방은 그 사람의 숫자에서 뽑는다

축 판정만 보고 템플릿을 읽어주면 다음 주에 같은 습관으로 돌아온다.
`references/coaching.md` 의 문장을 **지표에 있는 실제 숫자로 다시 쓴다.**

- `## 자동화 후보` 에 검증·빌드 계열이 잡혔으면 그 명령을 그대로 인용한다.
  "반복 작업을 자동화하세요"가 아니라 "`npx tsc` 를 481번 쳤습니다"
- `## 작업 방식` 의 스킬 호출이 적으면 그 수치를 짚는다
- 말버릇 상위가 상태 설명형이면 그 낱말과 횟수를 짚는다

숫자를 붙이면 처방이 남 얘기가 아니게 된다.

### 2. 이번 주에 할 것 하나만 남긴다

축 두 개에 대한 처방을 냈어도 **맨 마지막에 "이번 주에 할 것" 한 줄로 좁힌다.**
둘 중 더 작은 것, 오늘 30분 안에 끝나는 것을 고른다. 큰 것을 고르면 아무것도 안 한다.

### 3. 그 자리에서 만들어준다

처방을 말로 끝내지 않는다. **"지금 만들어드릴까요?" 를 묻고 승인하면 실제로 만든다.**

| 처방 | 만들어줄 것 |
| --- | --- |
| 반복 설명을 문서로 | `AGENTS.md` 에 절을 추가하고 초안을 쓴다 |
| 검증을 훅으로 | 훅 명령 한 줄을 제안하고 `settings.json` 에 넣는다 |
| 반복 절차를 스킬로 | `skill-creator` 를 부른다 |
| 새벽 문맥 유실 | `handoff` 스킬 설치를 안내한다 |

사용자가 거절하면 그대로 둔다. 다음 측정 때 같은 처방이 또 나오면 그때 다시 묻는다.

### 4. 다음 측정을 예약하라고 권한다

지표 마지막의 `## 지난 측정과 비교` 는 이력이 있어야 나온다.
첫 측정이면 **한 달 뒤에 다시 재자고 말한다.** `/schedule` 로 걸어둘 수 있다고 알린다.

처방이 먹혔는지는 다음 측정에서 숫자로 드러난다. 그게 이 스킬을 한 번 쓰고 마는
검사가 아니라 습관을 고치는 도구로 만든다.

### 반복이 보이면 스킬 생성 프롬프트를 만들어 준다

"스킬로 만들어보세요"에서 끝내지 않는다. **그 사람의 숫자로 채운 프롬프트를 통째로
만들어 주고 복사해서 붙이라고 한다.** 형식과 판단 기준은 `references/skill-prompt.md` 에 있다.

내는 조건은 셋 중 하나다. 같은 명령이 20회 이상 반복됐거나, 스킬 호출이 지시 100건당
5회 미만이거나, 같은 요청 유형이 말버릇에 반복해서 보일 때. 셋 다 아니면 내지 않는다.

**특정 스킬을 설치하라고 권하지 않는다.** 남이 만든 스킬 이름을 대는 대신
그 사람의 패턴으로 새로 만들게 한다.

### 자동화 후보 블록 규칙

`## 자동화 후보` 는 터미널에서 반복한 명령이다. 절 끝의 **"훅으로 내릴 만한 것"** 목록만
처방에 쓴다. `git status`, `grep` 같은 조회성 명령은 습관이지 자동화 대상이 아니다.
그걸 자동화하라고 하면 잘못된 조언이 된다.

### 작업 방식 블록 규칙

지표의 `## 작업 방식` 절은 **사람이 친 말이 아니라 실제로 무슨 도구를 불렀는지**를 센다.
말버릇보다 하네스 상태를 더 직접 보여주므로 코칭의 근거로 먼저 쓴다.

- **스킬 호출이 0이거나 지시 100건당 5회 미만이면** 그것을 짚는다. 도구는 수만 번 부르는데
  스킬은 안 부른다면 반복하는 절차를 아직 손으로 하고 있다는 뜻이다
- **서브에이전트 호출이 0이면** 나눌 수 있는 일을 혼자 하고 있는지 본다
- 도구 분포에서 한쪽이 압도적이면 사실만 적는다. `Bash 45%` 를 두고 "터미널만 쓴다"처럼
  단정하지 않는다
- 이 절이 비어 있으면(Claude Code 기록이 없거나 `--no-tools`) 통째로 뺀다

### 도구별 블록 규칙

지표의 `## 도구별` 절을 읽고, **10포인트 이상 벌어진 항목만** 짚는다. 비슷한 항목은
쓰지 않는다.

- 차이를 사실로 쓰고 원인을 단정하지 않는다. "코덱스를 덜 믿는다"가 아니라
  "물음표가 클로드 59%, 코덱스 39%다"
- 해석은 한 줄까지만 붙이고 추측임이 드러나게 쓴다.
  "도구마다 맡기는 일이 다를 수 있다" 정도
- 도구가 하나뿐이면 이 블록을 통째로 뺀다. 억지로 비교하지 않는다

### 결과지 규칙

- **숫자를 반드시 붙인다.** "새벽에 일하는 편이다"가 아니라 "새벽 22%"
- 칭찬과 지적의 균형을 맞추려 하지 않는다. 숫자가 한쪽으로 기울면 그렇게 쓴다
- 말버릇 순위는 그 자체로 재미다. 1위가 "다시" 라면 그걸 짚는다.
  질책 표현이 칭찬 표현보다 많으면 그 대비를 그대로 보여준다
- 인격을 평가하지 않는다. 발언 습관을 말한다
- 지표에 없는 추론을 하지 않는다. 저장소 이름으로 무슨 일을 하는지 짐작하지 않는다
- 이모지로 카드를 꾸미지 않는다. 숫자가 이미 세다

## 4. 저장과 발행

- 결과지를 `~/.claude/prompt-mbti/report-YYYY-MM-DD.md` 로 저장한다
- 지표 수치는 `analyze.sh` 가 `~/.claude/prompt-mbti/history.jsonl` 에 자동으로 남긴다.
  모델이 따로 적을 필요가 없다
- 같은 디렉터리에 이전 결과지가 있으면 **축이 바뀐 것만** 비교해 한 줄 덧붙인다.
  ("두 달 전에는 검증형이었다") 없으면 비교 블록을 넣지 않는다
- 사용자가 "공유", "이미지로", "화면으로" 라고 하면 Artifact 로 발행한다.
  발행 전에 `artifact-design` 스킬을 읽는다. 유형 카드를 크게, 근거 숫자를
  작게 놓고, 말버릇 순위는 표로 둔다

## 프라이버시

이 스킬이 읽는 건 각 도구의 세션 기록이다. 내가 타이핑한 지시가 전부 들어 있다.

- 스크립트는 **원문 지시를 출력하지 않는다.** 수치와 낱말 빈도만 낸다
- 낱말 빈도에도 사내 용어나 고객명이 올라올 수 있다. 발행하기 전에 말버릇 순위를
  다시 읽고, 밖에 나가면 안 되는 낱말이 있으면 **사용자에게 알리고 뺀다**
