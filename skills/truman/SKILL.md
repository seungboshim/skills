# 트루먼씨

나도 몰랐던 내 하루를 누군가 방송하고 있었다.

커밋 로그와 reflog, Claude 세션에 남은 내 발언은 이미 다 기록돼 있다. 이 스킬은 그걸
편집해서 3인칭 방송 대본으로 만든다. 회차가 누적되고, 어제 못 끝낸 일은 다음 회 예고가 된다.

**웃기려고 만든 스킬이지만 마지막 두 블록(제작진 노트·차회 예고)은 진짜 회고다.**
자료에 있는 사실만 쓴다. 없는 장면을 지어내면 이 스킬은 그냥 소설이 된다.

## 순서

1. 자료를 모은다
2. 지난 회차를 읽는다
3. 대본을 쓴다
4. 저장한다
5. 사용자가 원하면 방송 화면으로 발행한다

## 1. 자료 수집

수집기를 돌린다. 읽기 전용이고 네트워크를 쓰지 않는다.

**절대 경로로 부른다.** 이 스킬을 불러올 때 하네스가 알려준 base directory 를 그대로 쓴다.
작업 디렉터리는 사용자의 프로젝트라서 `bash scripts/collect.sh` 처럼 상대 경로로는 못 찾는다.

```bash
bash "<이 스킬의 base directory>/scripts/collect.sh" --out /tmp/truman-material.md \
  && cat /tmp/truman-material.md
```

base directory 를 모르면 이렇게 찾는다.

```bash
find ~/.claude ~/.config -name collect.sh -path '*truman*' 2>/dev/null | head -1
```

- 기본 구간은 **방송일**이다. 새벽 5시에 끊으니 새벽 3시 작업은 전날 회차에 들어간다
- 사용자가 특정 날짜를 말하면 `--day 2026-08-14`
- "아까 그거만" 처럼 짧은 구간이면 `--hours 6`
- 사용자가 세션 기록을 빼달라고 하면 `--no-claude`. 그러면 어록과 타임라인이 빠지고
  커밋·reflog 로만 써야 한다
- 저장소를 못 찾으면 `--root` 로 경로를 받는다

자료가 **거의 비어 있으면 대본을 쓰지 않는다.** 커밋도 발언도 없으면 그렇게 말하고 멈춘다.
"조용한 하루였다"로 한 문단 쓰는 건 괜찮지만 없는 사건을 채우지는 않는다.

## 2. 지난 회차 읽기

상태 파일: `~/.claude/truman/state.json`

```json
{
  "character": "그",
  "tone": "관찰 예능",
  "episodes": [
    {
      "id": "S01E03",
      "day": "2026-08-14",
      "title": "그는 왜 같은 파일을 열 번 열었나",
      "logline": "백로그만 고치던 오후, 그리고 18시 31분의 되돌리기",
      "cliffhangers": ["korean-tone 커밋 안 한 변경 3개", "inboxx-app stash 1개 (07/27)"]
    }
  ]
}
```

- 파일이 없으면 첫 회차다. `S01E01` 로 시작하고 상태 파일을 새로 쓴다
- **시즌은 달로 끊는다.** 첫 방송이 있던 달이 S01, 다음 달이 S02다. 회차는 그 시즌 안에서 1부터
- 지난 회차의 `cliffhangers` 를 오늘 자료의 `## 미완성` 과 대조한다. 같은 항목이 또 있으면
  **"N화 연속 등장"** 으로 쓴다. 이게 이 스킬에서 제일 아픈 부분이고 제일 웃긴 부분이다
- 앞 회차 `logline` 을 한 줄 인용해 "지난 회 줄거리"로 열어도 좋다

## 3. 대본

톤 프리셋과 완성 예시는 `references/narration.md` 를 읽는다. 상태 파일의 `tone` 이 기본이고,
사용자가 다른 톤을 말하면 그걸 쓰고 상태에 저장한다.

구조는 이 순서를 지킨다.

| 블록 | 내용 |
| --- | --- |
| 제목 | `S01E04 — 「제목」`. 제목은 관찰 예능 자막처럼. 결말을 미리 말하지 않는다 |
| 콜드오픈 | 하루에서 가장 극적인 한 장면을 시각과 함께 먼저 보여준다. reset·amend·긴 침묵이 후보다 |
| 1막 | 시작. 첫 발언 시각과 첫 커밋으로 하루의 문을 연다 |
| 2막 | 갈등. 반복 수정 파일, 되돌리기, 장면 전환이 잦았던 구간 |
| 3막 | 결말. 마지막 커밋과 마지막 발언. 끝났는지 아닌지를 정직하게 |
| 제작진 노트 | 관찰된 신호 3개 이하. 아래 규칙을 지킨다 |
| 차회 예고 | 미완성 항목에서 2~3개. 방치 일수를 붙인다 |

### 대본 규칙

- **3인칭 관찰자 시점.** 상태 파일의 `character`(기본 "그")로 부른다. 사용자를 2인칭으로 부르지 않는다
- **시각을 자주 박는다.** "오후 6시 31분" 같은 시각이 방송 느낌을 만든다
- **어록은 자막이다.** 자료의 어록을 큰따옴표로 **원문 그대로** 인용한다.
  오타도 고치지 않는다. `"스읍 일단 계속 구현해줘"` 의 "스읍"이 그날의 전부다
- **자료에 없는 사실을 쓰지 않는다.** 심리 묘사는 관찰된 행동에서만 추론하고,
  추론임이 드러나게 쓴다. "그는 지쳤다"가 아니라 "그는 같은 명령을 세 번 반복했다"
- 분량은 **800~1300자**. 읽는 데 2분. 넘기면 방송이 아니라 논문이다
- 이모지는 쓰지 않는다. 자막은 텍스트만으로 충분하다
- 교훈으로 끝내지 않는다. 마지막은 예고로 끊는다

### 제작진 노트 규칙

여기가 이 스킬이 실제로 쓰이는 이유다. 농담을 섞어도 되지만 **관찰 가능한 신호만** 쓴다.

쓸 수 있는 신호:

- 반복 수정 파일 1위와 그 횟수 (설계가 안 정해졌다는 신호)
- 되돌리기(`reset`·`amend`·`revert`) 횟수와 시각
- 가장 긴 침묵 구간 (막혔거나 쉬었다. 어느 쪽인지 단정하지 않는다)
- 문서 파일만 고친 구간 vs 코드를 고친 구간의 비중
- 장면 전환이 잦았던 시간대 (한 번에 두 저장소를 오갔다는 신호)
- 커밋 메시지의 톤이 무너지는 지점

쓰면 안 되는 것: 인격 평가, "생산성이 낮았다" 같은 총평, 자료에 없는 원인 추정.

## 4. 저장

- 에피소드: `~/.claude/truman/episodes/S01E04.md`
- 상태 파일에 이번 회차를 append 한다. `cliffhangers` 는 다음 회 예고와 대조하는 근거라
  **빠뜨리지 않는다**
- 대본은 터미널에도 그대로 출력한다. 사용자는 파일을 열지 않는다

## 5. 방송 화면 (선택)

사용자가 "화면으로 보여줘", "방송처럼", "공유할래" 라고 하면 Artifact 로 발행한다.
발행 전에 `artifact-design` 스킬을 읽는다. 화면 구성은 이렇게 간다.

- 상단에 회차 카드: `S01E04`, 제목, 방송일, 러닝타임 대신 "발언 72건 · 커밋 28건"
- 본문은 대본. 자막 인용은 화면 하단 자막처럼 가운데 정렬 블록으로
- 하단에 제작진 노트와 차회 예고를 카드 두 장으로
- 어두운 배경 + 모노스페이스 시각 표기. 다크·라이트 둘 다 나오게 토큰을 잡는다

## 하지 않는 것

- 자료를 수집하려고 네트워크를 쓰지 않는다. 전부 로컬 파일이다
- 세션 기록에서 뽑는 발언은 **사용자가 직접 타이핑한 것**만이다. 도구 결과나 파일 내용은 안 읽는다
- 그래도 어록에 비밀이 섞일 수 있다. 발행(Artifact·공유) 전에는 어록을 다시 훑고
  자격 증명·고객명·미공개 정보가 있으면 **사용자에게 알리고 뺀다**
- 사내 저장소가 섞여 있으면 발행 시 저장소 이름을 가릴지 물어본다
